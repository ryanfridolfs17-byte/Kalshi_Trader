============================================================
  KALSHI BOT v2.0 — DEPLOYMENT & ADVANCED SETUP
============================================================

This guide covers how to run the bot 24/7, either on your own
computer or on a cheap cloud server ($5/month).


============================================================
  OPTION A: RUN ON YOUR COMPUTER
============================================================

Good for testing. The bot runs while your computer is on.

  1. Install Python 3.9+ from python.org
  2. Open Terminal / Command Prompt
  3. Create a project folder and navigate to it:
       mkdir kalshi_bot && cd kalshi_bot
  4. Install dependencies:
       pip install requests cryptography
  5. Place all bot files in this folder
  6. Save your private key as kalshi_private_key.pem
  7. Edit config.py with your API Key ID
  8. Run:
       python kalshi_bot.py

  To keep it running in background (Mac/Linux):
       nohup python kalshi_bot.py > bot_output.log 2>&1 &

  To stop it:
       kill $(pgrep -f kalshi_bot.py)


============================================================
  OPTION B: RUN 24/7 ON A CLOUD SERVER ($5/month)
============================================================

This is the recommended approach for continuous trading.

  SETUP ON DIGITALOCEAN (simplest):
  ----------------------------------
  1. Go to digitalocean.com, create account
  2. Create a Droplet:
     - Choose Ubuntu 24.04
     - Basic plan: $6/month (1 vCPU, 1GB RAM)
     - Choose nearest datacenter
     - Add your SSH key (or use password)

  3. SSH into your server:
       ssh root@YOUR_SERVER_IP

  4. Install dependencies:
       apt update && apt install -y python3 python3-pip
       pip3 install requests cryptography --break-system-packages

  5. Create bot directory:
       mkdir /opt/kalshi_bot && cd /opt/kalshi_bot

  6. Upload your files (from your local machine):
       scp *.py root@YOUR_SERVER_IP:/opt/kalshi_bot/
       scp kalshi_private_key.pem root@YOUR_SERVER_IP:/opt/kalshi_bot/

  7. Secure the private key:
       chmod 600 /opt/kalshi_bot/kalshi_private_key.pem

  8. Create a systemd service for auto-restart:

       cat > /etc/systemd/system/kalshi-bot.service << 'EOF'
       [Unit]
       Description=Kalshi Trading Bot
       After=network.target

       [Service]
       Type=simple
       User=root
       WorkingDirectory=/opt/kalshi_bot
       ExecStart=/usr/bin/python3 /opt/kalshi_bot/kalshi_bot.py
       Restart=always
       RestartSec=60

       [Install]
       WantedBy=multi-user.target
       EOF

  9. Enable and start:
       systemctl daemon-reload
       systemctl enable kalshi-bot
       systemctl start kalshi-bot

  10. Check status:
       systemctl status kalshi-bot
       journalctl -u kalshi-bot -f    (live log output)

  To stop:     systemctl stop kalshi-bot
  To restart:  systemctl restart kalshi-bot

============================================================
  V2.0 STRATEGY BREAKDOWN
============================================================

The bot runs 6 strategies simultaneously, each backed by
real research or quantitative logic:

  S1: FAVORITE-LONGSHOT EXPLOIT
  ─────────────────────────────
  Source: Whelan & Karl (2025), UCD Working Paper
  Finding: Contracts priced <10¢ lose 60%+ of money invested.
           Contracts priced 55-85¢ earn small positive returns.
  Action: Buy favorites in the 55-85¢ zone; fade cheap longshots.
  Why it works: Retail traders overweight lottery-type bets.

  S2: SPREAD ARBITRAGE
  ────────────────────
  If YES ask + NO ask < 98¢, you can buy both and guarantee
  profit when the market resolves. Pure math, zero risk.
  Why it works: Inefficient order flow, especially low-liquidity
  markets and around news events.

  S3: ORDERBOOK IMBALANCE
  ───────────────────────
  When there's 3x+ more buying pressure on one side,
  informed traders are likely positioning. Follow them.
  Why it works: Market makers and insiders leave footprints.

  S4: WEATHER MODEL EDGE (strongest strategy)
  ────────────────────────────────────────────
  Source: Kalshi's own blog recommends this approach
  Method: Fetch NWS (National Weather Service) forecast data
          via their free API. Compare forecast temperature against
          Kalshi market prices. When they diverge >8%, trade.
  Why it works: Many traders use AccuWeather/iPhone Weather,
  which are less accurate than NWS models. Kalshi settles on NWS.

  S5: MEAN REVERSION
  ──────────────────
  When prices spike >12¢ in a short period, they overshoot
  and typically revert ~30%. Trade against the spike.
  Why it works: Emotional overreaction to news.

  S6: MAKER STRATEGY (always active)
  ──────────────────────────────────
  Source: Same academic paper shows Makers earn higher
  returns than Takers across all contract types.
  Action: ALWAYS use limit orders, never market orders.
  Why it works: Better fills, no slippage, maker rebates.


============================================================
  HONEST ASSESSMENT OF EXPECTED PERFORMANCE
============================================================

  What academic research says:
  - Average Kalshi contract returns: -20% (before fees)
  - Favorite zone (55-85¢): small positive returns
  - Longshot zone (<10¢): -60% returns
  - Makers outperform Takers by ~5-8%

  What this means for the bot:
  - By avoiding longshots and using limit orders, we're
    already in the profitable subset of trades
  - Weather strategy has the highest expected edge (~8-15%
    when NWS data diverges from market price)
  - Realistic expectation: 5-15% return on invested capital
    per month IF the bot finds good opportunities
  - Not every scan will produce a trade — that's by design
  - Some months will be negative. Variance is real.

  What this bot does NOT guarantee:
  - Consistent daily profits (markets are unpredictable)
  - Risk-free returns (arbitrage aside, all trades can lose)
  - Beating sophisticated quant firms on speed

  The edge is: being systematic, patient, and data-driven
  while most participants trade on gut feeling.


============================================================
  MONITORING & ITERATION
============================================================

  After running for 1-2 weeks:

  1. Review trade_history.json
     - Which strategies produced the most trades?
     - Which strategies were most profitable?

  2. Tune parameters in config.py:
     - If bot isn't finding trades: lower MIN_EDGE or MIN_VOLUME
     - If bot is losing: raise MIN_EDGE, lower MAX_AUTO_TRADE_CENTS
     - If weather strategy works well: consider expanding budget

  3. Come back to Claude to:
     - Analyze your trade history
     - Add new strategies
     - Add email/SMS notifications
     - Build a performance dashboard
     - Integrate additional data sources
